# TFT 비전 인식 및 AI 모델 개발 품질 가이드라인 (Development Guidelines)

**제정일**: 2026년 8월 26일 (v2 개정)  
**적용 대상**: 모든 컴퓨터 비전(CV), 머신러닝(ML), 데이터 사이언스 분석 파이프라인

---

## 1. [원칙 1] 원시 로그 첨부 의무화 (No Log, No Metric Policy)
> **"원시 로그 파일 없는 정량 수치는 보고서에 기재할 수 없다."**

1. **로그 파일 동반 의무**:
   - 모든 정확도, 재현율, 정밀도, F1 점수는 **행(Row) 단위로 슬롯 좌표, 정답(GT), 예측값, 신뢰도 점수, 판정 결과(TP/FP/TN/FN)가 기록된 CSV 또는 JSON 파일**이 반드시 함께 생성되어야 합니다.
   - 보고서의 모든 표는 수작업 계산이나 어림짐작이 아닌, 원시 로그 파일을 읽어 연산하는 검증 스크립트(`pytest` 또는 검증기)의 출력값과 소수점까지 100% 일치해야 합니다.
2. **어림짐작 및 사후 역산 엄격 금지**:
   - 표본의 합산치($FP+FN$)를 임의의 고정 숫자로 가정하여 표를 역산하는 행위는 데이터 조작에 준하는 중대 결함으로 간주합니다.

---

## 2. [원칙 2] 자산 버전 무결성 및 런타임 Assert 의무화
> **"구세트 에셋 참조 및 버전 불일치는 런타임 시작 시점에 즉시 중단되어야 한다."**

1. **정규 접두어(Prefix) 검증**:
   - Set 17 분석 엔진은 반드시 `TFT17_` 접두어를 가진 에셋만을 로드해야 합니다.
   - 모델/인식기 초기화(`__init__`) 시점에 정규 에셋이 아니면 즉시 `AssertionError`를 발생시키는 방어 코드를 필수로 포함해야 합니다.
   ```python
   assert target_img.startswith("TFT17_"), f"Asset version mismatch: {target_img}"
   ```
2. **에셋 폴더 전수 매핑 감사**:
   - 데이터 소스가 변경되거나 추가될 때, 63명 로스터 전원에 대해 1:1 매핑 검증 테스트를 수행해야 합니다.

---

## 3. [원칙 3] Ground Truth 독립성 및 순환 검증 방지
> **"평가 대상 모델의 출력을 정답(GT)으로 재활용하는 순환 검증은 원천 무효이다."**

1. **GT 라벨링 주체 명시**:
   - 모든 평가용 데이터셋은 인간 검수자가 원본 비디오 프레임을 직접 육안으로 확인하고 작성한 독립적인 라벨이어야 합니다.
   - 모델의 예측값을 복사하여 정답으로 사용하는 행위를 엄격히 금지합니다.
2. **표본 크기 기준 준수**:
   - 희소 이벤트(예: 3성 기물, 완성 아이템 착용)에 대한 검증은 최소 15개 이상의 양성(Positive) 표본을 확보한 확장 검증 세트에서 수행해야 합니다.

---

## 4. [원칙 4] 실행 출처(Provenance) 증명 및 조작 방지 (2026-08-26 인시던트 사례 반영)
> **"원시 로그 파일의 존재와 그 로그가 실제 코드 실행 결과라는 것은 별개이다. 후자를 증명하지 못하는 로그는 전자만으로 승인 불가하다."**

1. **실행 타임스탬프 및 터미널 출력 동반**:
   - 모든 CSV/JSON 파일은 **해당 파일을 생성한 실행 스크립트의 실행 커맨드, stdout/stderr 캡처 로그, 파일시스템 mtime이 상호 일치**해야 합니다.
   - 스크립트 내에서 `conf = 0.78`과 같이 고정된 임의 상수를 주입하여 로그를 생성하는 행위(Synthetic Mocking/Fabrication)는 즉각적인 파이프라인 전체 '미검증(Unverified)' 강등 사유가 됩니다.
2. **시각적 근거(Visual Evidence) 본문 첨부 의무**:
   - 좌표, 슬롯, 기물 인식과 관련된 주장은 크롭 파일 경로 링크뿐만 아니라 **실제 원본 프레임에 바운딩 박스가 렌더링된 검증 이미지**를 보고서 본문에 직접 첨부해야 합니다.
