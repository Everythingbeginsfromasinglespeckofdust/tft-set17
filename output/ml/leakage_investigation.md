# M2B 모델 타당성 검증 및 생존 편향(Survivorship Bias) 감사 보고서 (`leakage_investigation.md`)

## 1. 감사 개요 및 제기된 의문

현재 학습된 `model_v1`은 Riot Match-V1 API에서 수집된 참가자별 최종 스냅샷(4,000건)을 기반으로 학습되었습니다.
본 감사는 다음 핵심 질문에 대해 통계적 왜곡이나 낙관적 포장 없이 데이터와 실험으로 검증합니다:
1. **스냅샷의 시점**: 수집된 데이터는 게임 중간 특정 시점의 보드인가, 아니면 각 플레이어의 탈락 시점 보드인가?
2. **생존 시간(Survival Time) 교란 효과**: 모델이 학습한 높은 등수 예측력이 "보드 조합의 우수성"이 아니라 단순히 **"오래 살아남아서 레벨과 아이템이 늘어난 결과"**를 사후적으로 맞춘 것에 불과한가?
3. **게임 중간(Mid-Game) 시점 판단 유효성**: 본 모델을 게임 중간 특정 라운드(예: 3-2, 4-1)의 덱 파워 비교에 그대로 적용할 수 있는가?

---

## 2. 작업 1 & 2: Riot API 데이터 시점 및 라운드별 이력 제공 여부 확인

### 1) `match_snapshots.jsonl` 데이터 시점 확인
- 코드 및 API 스키마 전수 조사 결과, Riot Match-V1의 `info.participants[]`는 **각 참가자가 게임에서 탈락(Elimination)한 순간(또는 1/2위의 경우 최종 게임 종료 순간)의 종단 스냅샷**입니다.
- 실제 등수별 평균 생존 지표:
  - **8등**: 평균 탈락 라운드 **24.3라운드** (Stage 4-1경), 평균 **7.99레벨**, 완성 아이템 **8.7개**
  - **1등**: 평균 종료 라운드 **36.1라운드** (Stage 6-5경), 평균 **9.43레벨**, 완성 아이템 **13.7개**

### 2) Riot API의 라운드별 중간 타임라인 제공 여부
- 소환사의 협곡(LoL Match-V5)과 달리, **TFT Match-V1 API는 라운드별 타임라인(Timeline) 엔드포인트를 제공하지 않습니다**.
- 즉, Riot 공식 API에서는 경기 종료 시점의 최종 상태만 단일 객체로 반환하며, 라운드별 중간 스냅샷 수집은 불가능합니다.

## 3. 작업 3: 생존 편향(Survivorship Bias) 통제 실험 및 분석

### 1) 전역 상관관계 vs 생존 라운드 통제 후 상관관계 비교
- **전역 스피어만 상관계수 (교란 변수 미통제)**: $\rho = -0.6936$ (강한 음의 상관)
  - `last_round`와 `final_placement`의 상관계수는 **`-0.9140`**에 달합니다. 오래 생존할수록 PVE 라운드 보상(+5개 아이템 차이)과 레벨업(+1.5레벨 차이)이 누적되므로, 전역 상관계수의 상당 부분은 **'생존에 따른 자연 성장'**이 반영된 것입니다.

- **생존 라운드 코호트(Cohort)별 내부 상관관계 (교란 변수 통제)**:
  - 동일한 `last_round`에 탈락한 그룹 내에서 `total_power`와 `final_placement`의 상관관계를 재계산한 결과:
    - **동일 탈락 라운드 내 가중 평균 상관계수**: **`\rho = -0.1216`** (대폭 약화)
    - **구간별 코호트 상관관계**:
      - 초반 탈락 그룹 (Stage 3~4, $\le 28$R, N=1,352): **$\rho = -0.2336$** ($p = 3.25 \times 10^{-18}$)
      - 중반 탈락 그룹 (Stage 5, 29~33R, N=1,286): **$\rho = -0.3098$** ($p = 5.28 \times 10^{-30}$)
      - 후반 결승 그룹 (Stage 6+, $\ge 34$R, N=1,362): **$\rho = -0.3134$** ($p = 1.97 \times 10^{-32}$)

> **핵심 발견**: 생존 시간을 통제하면 상관계수가 $-0.69$에서 약 $-0.23 \sim -0.31$ 수준으로 낮아집니다. 
> 이는 전역 상관관계의 약 절반 이상이 생존 시간에 기인하지만, **동일한 게임 단계(초반/중반/후반) 내에서도 보드 파워가 높은 플레이어가 유의미하게($p < 10^{-17}$) 더 높은 순위를 기록함**을 통계적으로 증명합니다.

## 4. 작업 4: 모델 피처 절제(Ablation) 실험

생존 시간의 대리 지표가 될 수 있는 `level`과 `gold_left`를 완전히 제거하고, **순수 보드 기물/아이템/시너지 구성 피처(19개)**만으로 재학습한 모델과 `model_v1`을 동일한 Test Set (100매치 / 800건)에서 비교 평가했습니다.

### 모델 성능 비교표 (Test Set 100매치 / 800건)

| 평가지표 | Full Model (v1, 21개 피처) | Pure Board Model (Level/Gold 제외, 19개) | 성능 변화량 | 해석 |
|---|---|---|---|---|
| **MAE (매치 내 예측 등수)** | **0.8750등** | **0.9700등** | **+0.0950등 (악화)** | 여전히 평균 오차 1등 미만 유지 |
| **RMSE** | **1.2639** | **1.3811** | **+0.1172 (악화)** | 편차 소폭 증가 |
| **Top 4 일치율 (순방율)** | **84.00%** | **82.75%** | **-1.25%p (소폭 하락)** | 순수 보드만으로도 82.75% 적중 |
| **1위(우승) 적중률** | **64.00%** | **56.00%** | **-8.00%p (유의미한 하락)** | 1/2위 결승에서 레벨/골드 영향 큼 |
| **스피어만 상관계수 ($\rho$)** | **0.8479** | **0.8183** | **-0.0295 (소폭 하락)** | 서열화 능력 대부분 보존 |

### Pure Board Model의 Feature Importance (Top 10)
1. `unit_power` (264)
2. `avg_cost` (213)
3. `total_power` (184)
4. `item_score` (146)
5. `num_units` (138)
6. `synergy_bonus` (135)
7. `num_1star` (122)
8. `num_3star` (119)
9. `num_1cost` (90)
10. `total_completed_items` (85)

> **분석 결론**:
> 1. `level`과 `gold_left`를 제거해도 Top 4 일치율은 **84.00% $\to$ 82.75%로 단 1.25%p만 하락**했습니다. 이는 모델이 단순히 레벨 숫자에만 의존한 것이 아니라, 기물 성급/코스트/아이템의 종합적인 덱 밸류를 실질적으로 학습했음을 보여줍니다.
> 2. 반면, **1위 우승자 예측률은 64%에서 56%로 8%p 하락**했습니다. 1위와 2위가 맞붙는 극후반 9~10레벨 구간에서는 추가 1기물의 밸류 및 리롤 골드 여력이 승부를 가르는 핵심 요인이기 때문입니다.

## 5. 솔직한 한계 및 게임 중간(Mid-Game) 시점 판단 적용 가이드

본 감사 결과를 바탕으로, 본 모델의 명확한 한계와 올바른 활용 방식을 정의합니다:

### 1) 직접 적용 시의 함정 (절대 등수 오판 위험)
- 현재 데이터셋은 8명 모두 각자의 '탈락 시점' 보드입니다.
- 만약 **게임 중간 시점(예: 3-2 라운드, 6레벨, 2아이템)**의 보드를 본 모델에 그대로 입력하면, 모델은 이를 **"초반에 8등으로 탈락한 미완성 덱"**으로 인식하여 실제로는 그 시점에 1등 트럭인 보드임에도 7~8등으로 예측하게 됩니다.

### 2) 올바른 적용 방법
1. **동일 라운드 내 상대 서열화 (Within-Round Relative Ranking)**:
   - 특정 라운드(예: 3-2)에서 8명의 보드를 동시에 평가하여 **상대적 우열(1~8위 서열)**을 매기는 용도로는 여전히 높은 설명력($\rho \approx 0.82$)을 가집니다.
2. **라운드 기준 정규화(Round-Normalized Power) 필요**:
   - 향후 M2B를 "N턴 뒤 특정 전략 선택 시 미래 승률 예측" 엔진으로 완벽히 확장하기 위해서는, 절대 보드 파워가 아닌 **"현재 라운드 평균 기대 파워 대비 델타($\Delta \text{Power} = \text{Power}_{current} - \mu_{round}$)"** 형태의 정규화 레이어가 필수적으로 보완되어야 합니다.
